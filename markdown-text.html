Markdown text

Markdown text renders dynamic content across platforms. It maps common Markdown to Pulse type styles, so text from a content system or an API looks the same on web, iOS and Android.

Usage

When to use

  • The text comes from somewhere else and can change, such as care plan steps or help articles.
  • The content mixes headings, paragraphs, lists and links.

When not to use

  • Text you write into a screen. Use the Pulse type styles directly.

Markdown and type styles

Markdown text supports these properties. The right column is the live component.

  • Bare links such as https://www.example.com also become links.
  • Headings use the matching space-between-heading-N-body token before the text under them. Paragraphs and lists use space-between-body.

Placement

Padding around the content is up to the team using it. Until Pulse controls more of an app's layout, padding standards can't be set at the system level.

Accessibility

Using Markdown text on a page still needs an annotated design review of the page-level design.

Annotations

  • Annotate Markdown text with the standard annotations. The headings and body in one block are part of the same component.
  • Inline links are their own tab stops.

In code

  • Headings are real h1 to h4 elements. Use headingOffset to move them down a level when the page already has an h1. They keep their look.
  • The component builds React elements and never inserts HTML, so HTML in the Markdown shows as plain text. Only https:, http:, mailto:, tel: and relative links become links.
  • Write link text that makes sense out of context.
