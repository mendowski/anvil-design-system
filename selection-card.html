Selection card

Selection card wraps a radio button or a checkbox with custom content, so choices carry more visual weight in step-by-step flows. Use it when people need supporting information about each option to decide.

Usage

Radio selection cards let people pick one option from a group. Checkbox selection cards let them pick several.

Use it when

  • There are only a few options
  • Each option needs supporting content beyond a short description
  • People need to see every option and its details at once

Don't use it when

  • There are many options: consider Advanced select.
  • Options don't need more than a short description: consider a Select input or Advanced select.
  • There isn't room to show every option: consider a Select input or Advanced select.

Product usage

  • Service requests: member name, age, assigned gender at birth
  • Choosing a pharmacy: name, address, distance and hours
  • Payment method: card number, issuer and expiration date

Placement

On web and mobile, center selection cards in their parent container.

Interaction

Selection cards can be single- or multi-select: people must pick exactly one, at least one, or up to a set number.

Accessibility

Using selection cards on a page still needs an annotated design review of the page-level design.

Keyboard

  • Tab to the group, then use the arrow keys to move between options.

Screen readers

  • Every visible text must be announced.
  • For radio cards, VoiceOver says "selected" or "unselected", and NVDA and JAWS say "checked" or "not checked".
  • Groups are announced differently: VoiceOver says "Radio group", NVDA "Grouping" and JAWS "Group".

In code

  • Each card is a <label> around a native radio or checkbox input, so the whole card is clickable and keyboard behavior comes from the browser.
  • Wrap a group in a <fieldset> with a <legend>, and give radio cards the same name.
  • An error message is linked to the card with aria-describedby.

Code vs. Figma.
  • There's no group component in code, unlike iOS (PulseSelectionCardGroup) and Android (SelectionCardGroup). Group the cards yourself, and put the error message on the last card.
  • Selection limits, such as "at least one" or "up to 3", are up to the page.
