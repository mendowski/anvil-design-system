Global footer

The global footer is the main navigation on mobile. It lets people switch quickly between the key sections of the app, stays fixed at the bottom of the screen, and persists across most views.

Usage

Use the global footer for the destinations people need most often, such as Home, Visits, Health log and Learning. It's part of Global navigation, with the Global header and the menus.

Anatomy

  1. 1
    Icon20px. The current tab uses the filled version.
  2. 2
    LabelOne or two short words. It carries the meaning; the icon helps people scan.

Variants and options

Placement

  • Pin it to the bottom of the screen, 16px from the sides and bottom, and above the phone's safe area.
  • Add bottom padding to the page so the last content isn't hidden behind it.
  • When people tap a tab, the current page eases out to the new one.

When to show it

Every page reached from the global footer shows it, and those pages use the default global header. Pages with the default header use the tab bar to move between the main sections.

Don't show it in

  • Signed-out flows
  • Second- and third-level flows, which use the focused task header
  • Menu pages
  • Progress tracker flows: those pages show only a Next or Continue button to move forward

Accessibility

Using the footer on a page still needs an annotated design review of the page-level design.

Links or buttons

  • Where a tab goes may change over time. Code it as a link if it takes people to a new page, or a button if it acts on the current page.
  • In code, pass href for a link or onClick for a button.

Screen readers

  • Teams need to be able to change the screen reader text for each tab.
  • Badges are read as part of the label, such as "Messages, 2 new".
  • The footer is a <nav> named "Main". Change the name with label. The current tab has aria-current="page".
  • Icons are decorative; the visible label names each tab.

Order and size

  • On mobile, the header's Back button comes last in the screen's swipe order.
  • Each tab is at least 52px tall.

Code vs. Figma.
  • Figma hides the labels when the screen is too narrow. The component keeps them and lets them wrap to two lines with 5 tabs. The icons-only example above uses a page style to show the Figma behavior.
  • The component doesn't stop you from passing more than 5 items or from opening a menu from a tab. Both are left to the page.
  • iOS and Android components are still pending.
