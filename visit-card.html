Visit card

Visit card shows one of the member's visits: past, requested, today's or upcoming. Each card shows the date and time, the provider and the care type, and can add details such as coverage, copay or a cancellation fee, with up to three actions.

What changed in 5.7.0

Visit-card-v2 replaces Visit-card. The content is reorganized around the provider, the footer is lighter, and two new properties cover prominent and canceled visits.

  • ChangedContent restructured; care type and description merged into one field
  • Newprominent property for more emphasis on today and tomorrow
  • Newcanceled property
  • NewArrow indicator for the card's main action
  • ChangedButton usage: small tertiary buttons in the footer
  • ChangedBorder color, elevation and border radius
  • ChangedText styles and color usage
  • RemovedProperty to turn off the description and main content
  • Deprecatedfeatured property

Anatomy

The biggest changes are to the time and the care type. Time now sits on its own above the header, and the header holds the provider's name. Care type is no longer a separate field: product teams include it in the description.

    DateMonth and day; past visits add the year.
  2. B
    Time, without time zonePreviously in the header.
  3. C
    Care iconVideo, phone and so on. Give it an accessible name.
  4. D

  5. E
    DescriptionPreviously two separate fields for care type and description.

Content

The description can run to several lines: who the visit is for, fees, or what happens next. Product teams need to be able to add each of these.

  • Write the header as the provider's name and credential, such as "Anita Sharma, MD". For requests without a provider yet, describe who they'll see: "First available care provider".
  • Start the description with the care type. Add one fact per line after it.
  • Show the time without a time zone.
  • Keep button labels to a short verb phrase: "Modify", "View invoice", "Cancel request".

Prominent visit cards

The new prominent property adds emphasis to Upcoming and Today cards. It puts the time first instead of the date, and is meant for visits in the next 48 hours: today and tomorrow.

Show "Today" or "Tomorrow" by comparing the visit date with the current date. Past and Custom types have no prominent style and look the same as usual.

As soon as possible

A prominent Today or Upcoming visit can be requested for "as soon as possible" instead of a set time. Put "ASAP" in the time.

Canceled visits

The new canceled property adds "Canceled" under the description. It works on Past, Upcoming, Today and Custom cards.

Prominent cards never show it. Prominent cards only appear in the to-do (ephemeral) section, and a canceled visit leaves that section, so it's never prominent.

Action configurations

A visit card holds up to three actions. Which ones, and how they look, depends on the type. Inline tertiary buttons wrap to a new line when the labels don't fit on one.

Tap targets

Each button has its own tap target, as a button or a link. When the card has a main action, the area above the buttons is the tap target for that action. Past, Upcoming and Today cards show the arrow for it; Custom cards can have a main action but never show the arrow. Prominent cards don't support a main action, so only their buttons are interactive.

Deprecated: featured

The featured property is deprecated, and the card no longer has a max width. Featured only applied to web. To call out the next visit, use a prominent card instead.

Before: featured (web only)
Now: prominent, with a primary button

Code vs. Figma. With href, the hit area covers the whole card, with the buttons layered above it. Figma limits it to the area above the buttons. The eyebrow and date use brand-human-care-* tokens, which replace Figma's status-branded colors.
